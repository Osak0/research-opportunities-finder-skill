# 证据判定规则

本文件规定“什么能算证据、每个条件怎么判、时效怎么分、归属怎么处理”。所有判断以原文为准；没有原文就是未知，不推断。

## 1. 证据等级

| 等级 | 定义 | 用法 |
|---|---|---|
| **E1** | 身份可核实的原始页面：高校、研究机构、实验室或企业官方发布的教师与团队介绍、招生信息及项目公告 | 可作为肯定判断的直接证据；必须能打开、能读到原句 |
| **E2** | 身份可核实的公开账号发布的原始招募信息（学院/实验室实名账号、教师实名账号），且内容完整、可定位 | 可作为直接证据；逐项核对适用对象、年份和时效，并保留原链接 |
| **E3** | 只有搜索摘要、转载、截图、二手汇总；页面打不开；来源互相矛盾；无法确认发布者身份 | 只能作为**待核实线索**，不能支撑“明确满足”“当前仍在招”等肯定判断 |

规则：

- 每条影响筛选的判断附**原句**、**直达页面**、**发布日期（若有）**、**核查日期**。
- 原句要能独立读懂，不要只截“欢迎联系”四个字；保留年级、专业、时间等限定语。
- 直达页面指能直接看到该原句的 URL，不是搜索结果页、列表页或首页。
- 页面打不开时，不以缓存摘要替代原文；记为待核实线索并写明原因。
- 同一事实有 E1 与 E3 两个来源时，以 E1 为准；E3 只用于提示需要继续核验。
- 来源冲突时，不挑选对结果有利的一方；保留冲突，降为待核实线索，或分别注明两种说法。

## 2. 五个条件字段

状态只用三种：**明确满足**、**明确冲突**、**未说明**。

### 2.1 研究方向（direction）

- **明确满足**：原文有可归属到该教师/团队的课题、论文、研究介绍，且与学生的方向要求相关。
- **明确冲突**：原文明确说明不做该方向，或团队方向与要求明显无关。
- **未说明**：只有职称、课程、工具要求，或方向描述无法归属到具体研究。
- 仅要求学生会使用 Python、PyTorch、GPT 等工具，**不构成方向匹配**。
- 泛泛写“人工智能”“大数据”时，优先找更具体的研究介绍；只有泛词时按未说明或弱线索处理，不硬判满足。

### 2.2 本科生资格（undergrad）

- **明确满足**：原文明确招收/欢迎本科生参与科研、科研训练、实习、进组或毕业设计（以科研为主）。
- **明确冲突**：原文明确只招研究生、只招已录取硕士/博士，或明确不接收本科生。
- **未说明**：只列硕士/博士招生名额、只写“招生”未写对象、只写课程或保研要求。
- 研究生招生公告不能推出本科生资格；“欢迎报考”不等于“欢迎本科生参与科研”。

### 2.3 年级（grade）

- **明确满足**：原文写欢迎该年级（如“大二、大三”“低年级本科生”）。
- **明确冲突**：原文限定其他年级且不含学生所在年级（如只招大三，学生为大二）。
- **未说明**：只写“本科生”，没有年级限定。
- “本科生”不自动等于“任何年级”；学生提出年级硬条件时，未说明仍是未知，不当作满足。

### 2.4 校籍（school）

- **明确满足**：原文明确面向申请人所属学校或明确接受其校籍类别。
- **明确冲突**：原文限定特定学校或校籍类别，且申请人明确不符合。
- **未说明**：原文未说明校籍限制，或判断所需的申请人校籍未知。
- 区分招募机构与申请人校籍，根据原始公告判断是否接受外校或国际申请者。

### 2.5 时间要求（time）

- **明确满足**：学生提出了时间条件，原文给出每周投入、持续时长、开始时间或工作地点，且与学生条件相容。
- **明确冲突**：学生提出了时间条件，原文要求与学生的可投入时间/地点明确冲突（如学生只能线上，公告要求每周到校 8–10 小时）。
- **未说明**：学生提出了时间条件但原文没有写；或学生没有提出时间条件，原文的时间要求只作为待确认信息展示，不判“明确满足”。
- 公告里的“每周 8–10 小时”是硬信息，要保留原句；学生没提时间时，作为待确认项展示，不替学生判断能否满足。

## 3. 时效五类

每条结果必须且只能标一类：

### 3.1 明确有效期（deadline_open）

- 公告给出明确截止日期，且核查日期未晚于截止日期（含当天）。
- 必须记录截止日期原句和发布日期。
- 截止日期临近时提示学生尽快确认，但不替学生判断“还来得及”。

### 3.2 长期接收（long_term）

- 原文明确写“常年招收”“长期招收”“长期有效”等。
- 保留原意，不改写成“当前有 N 个名额”。
- “长期接收”仍可能需要联系确认本期容量；在待确认项里写“当前名额”。

### 3.3 曾发布-当前名额待确认（posted_quota_tbd）

- 有招募公告、项目说明或“欢迎本科生联系”的原始表述，但没有截止日期，或无法确认本期是否还有名额。
- 这是最常见的类别。**有发布日期、无截止日期，不能写成“当前仍在招”。**
- 公告较新也只说明“曾发布”，不说明“现在有名额”；在待确认项里写“当前名额/是否仍接收”。

### 3.4 已截止（deadline_expired）

- 公告有明确截止日期，且核查日期晚于截止日期。
- 过期公告不能作为当前名额的依据，不进入“明确匹配”组，也不进入“资格待确认”组。
- 可以作为历史线索提及，但必须标明“已截止”，不得暗示仍可申请。

### 3.5 未找到本科生招募信息（none_found）

- 查过团队介绍、招募说明及项目公告等相关页面，没有找到本科生招募表述。
- 这是“没找到”，不是“不招”；不要写成“明确冲突”。
- 记录实际查过的页面，避免把“没查”说成“没有”。

## 4. 归属规则

按**招募主体**和**学生实际加入的团队**判断：

| 情形 | 处理 |
|---|---|
| 机构或课题组招收学生加入本组 | 符合用户范围时纳入，标明招募机构和团队 |
| 多个机构或团队合作招募 | 符合用户范围时纳入，注明合作方、实际工作地点、指导归属；未知标待确认 |
| 岗位由其他团队转发 | 依据原始公告确定归属，仅在符合用户范围且工作内容以科研为主时纳入 |
| 联合项目，无法核实学生实际加入哪个团队 | 只保留为待核实线索，不进入明确匹配 |
| 同一项目多个转载 | 合并为一条，优先原文；转载只作辅助 |
| 同一教师多个不同项目 | 分别保留，各自记录申请条件与时效 |

## 5. 分组规则

结果分三组：

- **明确匹配（confirmed）**：公开依据满足本轮全部硬条件，且时效不是“已截止”或“未找到本科生招募信息”。
- **资格待确认（pending）**：方向符合本轮要求（本轮未限定方向时不要求方向证据），但本科生资格、年级、校籍、时间或当前名额至少一项未说明，且时效不是“已截止”。
- **待核实线索（lead）**：身份、归属、来源或证据等级无法确认（E3、页面打不开、来源冲突、联合项目归属不明）。

硬条件由学生本轮明确提出的要求决定；学生没有要求的条件，未知不阻止 confirmed，但要保留在待确认项里。硬条件明确冲突的候选直接排除，不进入任何组。已截止的公告不进入 confirmed 或 pending；如保留，只能作为历史说明。零个明确匹配是有效结果；不得用 pending 或 lead 填充 confirmed。

## 6. 复核清单

交付前逐条自查：

- [ ] 每个“明确满足/明确冲突”都有原句和直达页面。
- [ ] 每个判断都有核查日期；有发布日期的公告都记了发布日期。
- [ ] 方向匹配能归属到教师/团队，不是工具要求。
- [ ] 研究生招生公告没有被当成本科生招募。
- [ ] 没有把“本科生”自动当成“所有年级”。
- [ ] 没有把“有公告”当成“当前有名额”。
- [ ] 过期公告没有进入明确匹配或资格待确认。
- [ ] 岗位归属已依据原始公告核实；合作项目写了合作方和地点；归属不明只做线索。
- [ ] 页面打不开/只有摘要/转载的条目没有进入明确匹配。
- [ ] 待确认项写的是真正未知的条件，不是已核实的结论。
