# 西交大检索手册

本文件只记录可复用的检索路径与操作细节。证据怎么判、结果怎么写，分别见 `evidence-rules.md` 和 `result-format.md`。

## 1. 门户入口

- 教师门户首页：`https://gr.xjtu.edu.cn/`
- 学院列表：`https://gr.xjtu.edu.cn/units.jsp?urltype=tree.TreeTempUrl&wbtreeid=1021`
- 教师列表模板：
  `https://gr.xjtu.edu.cn/units_teacherlist.jsp?urltype=tsites.CollegeTeacherList&wbtreeid=1021&st=0&id=<学院id>&lang=zh_CN`

计算机科学与技术学院教师列表（默认顺序、分页）：

`https://gr.xjtu.edu.cn/units_teacherlist.jsp?urltype=tsites.CollegeTeacherList&wbtreeid=1021&st=0&id=1025&lang=zh_CN`

### 1.2 教师分页 JSON 接口

教师列表页由脚本异步加载。直接请求页面只能拿到骨架，完整列表用：

`https://gr.xjtu.edu.cn/system/resource/tsites/getsitelistcontent.jsp`

常用参数：

- `collegeId=1025`
- `start` / `end`：本页起止序号
- `startnum` / `endnum`：与上相同，门户前端会同时带
- `viewUniqueId=u10`
- 其他门户前端固定参数可照抄列表页请求

响应是 **UTF-8 JSON**，不是 GBK。解析后按返回顺序记录教师姓名、职称、主页链接。分页抓取时保留序号，保证“默认顺序前 20 位”之类选样可复现。

## 2. 教师主页要看哪些栏目

教师主页常见路径：

| 内容 | 路径形态 | 说明 |
|---|---|---|
| 首页 | `/zh_CN/index.htm` | 研究领域、个人简介、联系方式、团队 |
| 招生信息 | `/zh_CN/zsxx/<栏目id>/list/index.htm` | 研究生/本科生招生栏目，常分页 |
| 自定义栏目 | `/zh_CN/zdylm/<栏目id>/list/index.htm` | 老师自建的“招生”“科研训练”等栏目 |
| 新闻/公告 | `/zh_CN/article/<栏目id>/content/<文章id>.htm` | 项目招募、招生说明常发在这里 |
| 我的新闻列表 | 首页导航“我的新闻” | 只读首页会漏掉关键公告 |

检索顺序建议：

1. 首页研究领域与简介，确认方向可归属到该教师/团队。
2. **招生信息**栏目，看是否明确写本科生。
3. **我的新闻**列表，逐条看标题含“招生/招募/实习/科研训练/加入/本科生/大二/大三/名额/长期/常年”的公告。
4. 科研项目、论文成果、实验室/团队链接，补足具体课题与合作方。
5. 有院内通知、实验室独立站时再交叉核验。

## 3. 公开搜索路径

关键词组合（中英文都试）：

- 招募对象：`本科生`、`本科`、`大二`、`大三`、`大四`、`低年级`、`undergraduate`、`bachelor`
- 机会类型：`科研实习`、`科研训练`、`进组`、`加入我们`、`开放课题`、`大创`、`创新创业`、`助研`、`research internship`
- 时效：`常年`、`长期`、`持续招收`、`名额`、`截止`、`deadline`
- 方向：具体方向名 + 同义词 + 英文缩写（如 `智能体`/`Agent`/`LLM Agent`、`计算机视觉`/`CV`、`多模态`/`multimodal`）

搜索时把“方向词”和“招募词”分开组合，避免只用“招生”漏掉新闻公告，也避免只搜方向得到一堆论文。

`cs.xjtu.edu.cn` 从当前网络不可访问。不要把它当作已核验来源，也不要在结果中引用无法打开的旧站链接；改用 `gr.xjtu.edu.cn` 教师门户、可访问的学院页面或身份可核实的公开账号。

## 4. 双路径与预算

开放式搜索同时走两条路：

1. **门户路径**：学院列表 → 教师索引 → 教师主页 → 招生/新闻/项目/实验室。
2. **公开搜索路径**：方向词 + 招募词 → 学院通知、实验室页面、教师个人主页、项目公告、身份可核实的公开账号。

默认以**精读 20 位候选**为开发测试初始预算：

- 先记录发现到的候选池（教师/项目、来源、发现路径）。
- 优先精读有具体课题、论文、公告线索的页面；证据相当时兼顾院系覆盖。
- 同一教师的不同项目分别保留；同一项目的转载合并，优先原文。
- 预算用尽时写“本轮找到”，并说明未遍历的范围。

用户明确要求查全某个有限目录（例如“把计算机学院教师目录前 20 位都看完”）时，遍历该目录，对每位有方向线索的教师继续查招生/新闻；交付时写清实际覆盖人数、未能核验的页面和停止原因。

## 5. 常见坑

- **只读首页**：很多招募信息在“我的新闻”或“招生信息”子页。
- **把研究生招生当本科生招募**：招生信息只列硕士/博士名额时，本科生资格仍是“未说明”。
- **把“欢迎联系”当当前名额**：没有截止日期或名额说明时，只能标“曾发布-当前名额待确认”。
- **把旧公告当现在**：有发布日期、无截止日期的公告，不能证明今天仍在招；截止日期已过的公告标“已截止”。
- **把教师转发当校内机会**：企业自行招募、教师只是转发的岗位排除；校内团队与外部机构合作、学生实际加入校内团队的项目可纳入，但要写合作方和实际工作地点。
- **把工具要求当方向**：主页只写“要求会 Python/PyTorch”不构成方向匹配，必须有可归属的课题、论文或研究介绍。
- **把搜索摘要当原文**：摘要、截图、转载、打不开的页面只能作为待核实线索。
- **编码问题**：门户部分页面是 UTF-8，脚本读写统一显式 `encoding="utf-8"`；控制台中文乱码时设置 `PYTHONIOENCODING=utf-8`，不要因此改文件编码。
- **分页漏人**：教师列表和招生栏目都可能分页；记录实际读到的页数与条目数。
